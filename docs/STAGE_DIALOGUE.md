# Stage dialogue

Migration 033 is an explicit additive operation after migration 031. It is not applied automatically. The migration command refuses the repository's persistent Main database; use a disposable database for testing and arrange a separately authorized, backed-up production deployment. Missing or damaged dialogue schema causes the dialogue endpoints to return unavailable. No existing notes or general comments are migrated.

The currently implemented audience is limited to the manuscript's Author, its one accepted and non-revoked Initial or Final Editor invitation, and the inviting EIC if that account has an EIC role. The server resolves and snapshots this audience, the assignment and the stage. Initial Editing uses explicit pre-review evidence; Final Editing uses the accepted Author Agreement and its accepted EIC decision round. Clients cannot choose recipients or claim a round. Other audiences, including Reviewer and Formatter threads, are not enabled by this implementation.

Messages and thread snapshots are append-only. There is no edit, delete or close operation. Access is rechecked on each request, including Editor invitation revocation and disabled accounts. The original Author and eligible EIC can still read the historical thread after an Editor invitation is revoked; the revoked Editor cannot. New messages require the original assignment, current stage, matching round and active participants. A replacement Editor does not acquire the prior thread; the synthetic replacement test does not assert an existing replacement workflow.

The Author, Editor and EIC workspaces retain their existing Private Notes and, where authorized, Staff Conversation, and provide a separate Stage Threads disclosure. The audience is displayed before a thread is opened and again before sending. Reviewer, Formatter and broader cross-role dialogue policy remains undecided; no Author–Reviewer communication or reviewer identities are exposed through this feature.
