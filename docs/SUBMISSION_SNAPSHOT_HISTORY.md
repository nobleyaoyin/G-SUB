# Submission snapshot history

On a database with migration `017_ai_prescreening` installed and its immutable snapshot schema intact, a successful formal initial submission, initial resubmission or peer-review resubmission records a submission snapshot in the same database transaction. This happens whether `AI_PRESCREENING_ENABLED` is `true` or `false`. When AI is enabled, the existing pending AI job is also queued; when disabled, no AI job is created. The worker and analysis remain separately configured.

Each record refers to the submitted version's existing, uniquely named upload and records its SHA-256, format, manuscript, author, submission sequence, kind, round and server timestamp. Author and EIC history downloads verify the recorded digest against the bytes returned. Normal replacement uploads use a new path, so earlier submissions remain associated with their original files. The snapshot does not duplicate file storage or guarantee recovery if an administrator removes or modifies a stored file; missing or changed bytes fail closed on verified downloads.

Migration 017 must be installed through the supported migration process before relying on this history. Older databases without it retain the existing submission behavior and cannot produce these snapshot records. A partially installed or inconsistent snapshot schema is rejected rather than treated as trusted history. This change does not migrate any database, reconstruct legacy submissions or create AI jobs when the feature is disabled. Existing snapshot immutability triggers and status/transaction guards remain in force.
